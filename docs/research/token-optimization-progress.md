### Frozen-cache and transport invariants

- `resolveBlock` skips strings below 1,000 estimated tokens before hashing. Larger strings are queued by SHA-256 of their decoded text's UTF-8 bytes. The first cached `kept` or `compressed` verdict is reused without re-running compressors. The queue serializes decisions within the process; `CompressionCache.write` itself is not a cross-process first-writer lock.
- `decideBlock` requires a reduction of at least 10% in string length with the recovery marker included. It uses existing heuristics, then the optional `token-proxy` task for output still at least 8,000 estimated tokens. `summarizeToolResult` caps input at 24,000 estimated tokens, chunks it, and abandons a partial failed summary. No model task was invoked during inspection.
- Compressed entries live under `proxy-cache/<first-two-hash-characters>/` as original text, replacement text and a version-1 JSON verdict. Texts are written first and the record last through the existing atomic writers; only then may the replacement be used. Kept entries store only the verdict. Memory eviction does not remove disk records; there is no disk pruning path.
- Cache read/write filesystem failures leave the block unchanged. Unexpected compressor errors reach the server's fallback, which forwards the original body. Invalid records, different record versions and missing replacement files currently read as absent, so future work must preserve compatible version-1 records and legacy compressor IDs. Missing original text can still yield a compressed verdict; recovery reports that original as unavailable.
- The request buffer and decoded output are capped at 64 MiB. Oversized uploads switch to streaming passthrough. Decoding supports gzip, deflate, Brotli and zstd when the runtime provides it, with strict UTF-8 handling. Unchanged requests keep their received bytes and encoding; changed bodies receive corrected length/encoding headers. Responses and upstream error bodies are streamed unchanged; mid-stream upstream failure closes the client response.
- Failure/recovery eligibility guards do not exist yet. Explicit tool failure can therefore reach `resolveBlock` today. The next safeguards must run before cache lookup without changing stored verdicts; this inventory does not claim those safeguards are implemented.

### Unresolved limits

- The report is process-lifetime and in memory. Stats rows, a migration and aggregation are 06.1 to 06.5; the Settings panel is 07.3 and the dashboard view 07.4. Until then the data is visible through `maestro-cli models proxy status` (human and `--json`) and the `localModels:proxy:report` channel, which the renderer already receives.
- Attribution is by the newest results of each examined request. A client that resends a request is observed twice, a request skipped as busy loses its newest results, and the first request after a restart counts only its own newest results. Reads older than the newest 256 reads or 8 MiB are not examined, so a re-read whose baseline is that old shows as `first`.
- Working directories are the stored record's `projectRoot` and `cwd`. An agent's extra directories are not roots, so a read there is `outside-workspace`.
- Only requests the proxy reads are examined (a compress mode); passthrough bodies are streamed unread and an agent on an SSH remote cannot reach the proxy. The Responses `previous_response_id` and `conversation` shapes are refused by name, and Claude Code's Read in ranges is `partial-range`.
- Every figure is a 4-characters-per-token estimate against the text as the agent sent it. A re-read preview and an outline can describe the same result and are kept apart; where the proxy also shortened that result, `delivery` says `replaced` and the figure overlaps the realized reduction. Nothing measures what a model does with a delta or an outline.
- Size. The change adds 623 non-blank, non-comment production lines in 8 production files (the new module is 398), over the roughly 500 lines and 1 to 3 files this playbook asks of a task. 127 are type and label declarations in the shared contract and about 35 are zero initializers; the parts were written and tested together and are not split. Timings are from synthetic bodies and one machine. No packaged build was made (the final phase owns it) and no provider workload ran.
