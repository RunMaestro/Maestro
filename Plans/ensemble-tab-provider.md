# Ensemble tab provider design

Design for ENSEMBLE-08 task 1. This document specifies future implementation; it does not register the flag or change runtime behavior. Source baseline: `acappella` at `4beb4e244e80`, inspected 2026-10-17. The existing local edits to [[provider-translation-layer]] were read for acceptance status and left untouched.

## Decisions

| Code | Decision                                                                                                                                                                                |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1   | `Session.toolType` is the default for new/inheriting tabs. Optional `AITab.tabProvider` selects one tab's harness.                                                                      |
| D2   | The live native ID, usage and selected model/effort/Run on belong to the tab's effective provider. Its `providerSessions` map never contains that provider.                             |
| D3   | `turnProvider` is send-time ownership, not the next provider selection. In-flight events and finished turns retain that ownership.                                                      |
| D4   | Edit Agent changes inheriting tabs only. Explicit tab overrides survive, including an explicit choice equal to the new agent default.                                                   |
| D5   | Turning Ensemble off hides its controls and rejects its CLI verb. Existing overrides and captured queue items continue working; no data is moved or deleted.                            |
| D6   | Auto chooses tiers within the selected harness. Run on is remembered per harness per tab. Non-default harnesses use their own harness tier defaults, not the agent's tier targets.      |
| D7   | Desktop, phone and CLI share the selection operation and availability verdict. The next send uses the existing native translation gate.                                                 |
| D8   | No translation direction is native-certified. Local declared directions still require existing warning acceptance. SSH choices remain disabled because live SSH acceptance was skipped. |

## Data model and ownership

Add `tabProvider?: ToolType` to `AITab`, `ProviderSwitchTab`, `TranslationTab` and the runtime tab record/projections. Absence means inheritance. A named provider is an explicit pin, even when it equals `Session.toolType`; only the "Use agent default" action clears the pin. Do not infer a pin from an old `turnProvider` or a parked native ID. Reject terminal and unknown providers at the mutation boundary.

One selection resolver lives in `src/shared/maestro-lib/agents/providerSwap.ts`:

```text
resolveTabProvider(tab, agent) = tab?.tabProvider ?? agent.toolType
resolveTurnProvider(tab, agent) = tab?.turnProvider ?? resolveTabProvider(tab, agent)
```

`resolveTabProvider` serves the composer and a new send. `resolveTurnProvider` serves a captured turn, event, error, cost or History entry. A queue item uses `item.turnSettings.provider` first, then the selection resolver only for legacy items without provider capture. Neither resolver consults the Encore flag. Runtime ownership cannot change when a UI flag changes.

The two parking maps have different invariants:

- **Tab:** live fields belong to `resolveTabProvider(tab, agent)`; `providerSessions[effectiveProvider]` is absent.
- **Agent:** live override fields still belong to `agent.toolType`; `providerOverrides[agent.toolType]` is absent. A tab switch never moves this map or writes `Session.toolType`.

Keep `ProviderTabSession` as the canonical parked payload. Extend it and the live tab with `runOn?: RunOnTarget`; `undefined` means inherit the matching provider's default, and `{ type: 'provider' }` explicitly chooses that provider's cloud. `customModel: AUTO_MODEL` already represents the Auto selection. Never park the resolved Auto model in place of the selection. Extend the duplicated structural shape in `TranslationTab` to reuse the canonical payload through a type-only import, checking import cycles.

The tab's `turnModel`, `turnEffort`, `turnRunOn`, `turnRunOnSource` and `turnAuto` remain facts about its most recent turn. They must not be restored from another provider's selection or overwritten by a pill click. `tabSessionLaunch()` must compare the captured turn owner with the provider being resumed, not the agent default. When those differ, or translation replaced the native session, return no cache hold. This deliberately discards a possible warm-cache optimization after A -> B -> A instead of falsely treating B's last model/activity as A's cache. Do not add another per-provider cache-history map in this phase.

Add optional `turnProvider` to persisted `LogEntry`/runtime transcript records as well as the existing tab stamp. New assistant entries copy the captured turn owner; old untagged entries remain unknown unless native import supplies provenance. Extend `QueuedTurnSettings` with the Run on/routing snapshot described below, using the existing shared types. Do not reuse `tabProvider` as a historical log or queue field.

### Switching one tab

Add `switchTabProviderFor(tab, agent, providerOrInherit)` beside the resolver. Reuse `switchTabProvider()` from `translation/session.ts` for the actual park/restore; do not duplicate it or call the all-tabs `switchAgentProvider()` as a selection action.

1. Resolve the old effective provider before changing the pin. Validate the target, flag, host and direction through the shared availability decision. Re-read the tab inside the existing store mutation before committing.
2. Park the outgoing native ID, usage, custom model, custom effort and Run on. Restore the destination slot and remove it from the map. An unseen destination gets an empty native slot and its own defaults.
3. Set or clear `tabProvider`. A same-provider pin/inherit change changes only inheritance metadata. Preserve transcript, drafts, History preference, permission mode, Thinking preference, sibling tabs and the agent's SSH configuration.
4. Retain the latest authoritative native source in `pendingTranslation`, including when the destination already has an older native slot. Existing pending source wins until a new turn actually establishes a newer native owner. Switching A -> B -> A without a B send cancels the pending A -> B hop; never translate an empty B slot back over A.
5. Persist with `updateAiTab()` and the normal session persistence path. Runtime writes use the repository's equivalent tab mutation. The selection itself performs no native import, starts no process and adds no "translated" marker.

A busy tab may select the provider for its next send. Its process, `turnProvider` and frozen turn settings stay unchanged. `updateProviderSlot()` routes all later IDs/usage to the captured owner's live or parked slot using D2. If the outgoing turn has not emitted an ID yet, preserve its ownership/pending marker; translation waits for its completion and then re-reads the native ID. Do not interpret a temporarily missing ID as an empty conversation. Retain the current busy/migration collision checks and held-message behavior.

The next send calls `prepareTabForSend()` through `prepareProviderTranslationForSend()` before consuming a message or assembling resume arguments. It translates the latest source even if the destination has a stale ID. A failed, ambiguous or unaccepted plan holds the message with its captured settings. It neither launches an empty replacement conversation nor clears the source pointer. Only a committed report can produce the transcript translation marker. Warning acceptance remains operation-specific and is invalidated by changed source identity, account, scope or plan.

### Edit Agent, persistence and lifecycle

| Event                                        | Required result                                                                                                                                                                                                                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Edit Agent changes A to B                    | Park/restore agent overrides as today. Only tabs without `tabProvider` follow A to B. Native planning/commit covers that inherited subset, including closed and snoozed tabs. Explicit tabs keep their live provider slots and selections. A failure preserves the pre-change state. |
| Explicit tab already uses B                  | It remains pinned to B when the agent moves to B, and still stays B if the agent later moves to C. It is not translated or parked again.                                                                                                                                             |
| Agent model/effort changes                   | Tabs with no model/effort override inherit only the configuration for their effective provider. Tab-specific values still win.                                                                                                                                                       |
| Ensemble disabled                            | Hide provider pill, phone row, palette actions and shortcuts; `tab provider` read and write return the flag error. Existing mixed-provider conversations continue, and generic inspection stays truthful. Enabling it again restores the same selections.                            |
| Close / undo-close / snooze / wake / restart | Carry the whole tab record, parked map and pending source through closed histories, unified history, snoozed groups and orphaned busy tabs. Closing a running tab does not redirect its late events to the agent default.                                                            |
| New tab                                      | No `tabProvider`; inherits the current agent default. Creating a new tab does not copy the previously active tab's pin.                                                                                                                                                              |
| Fork / reopen a native History conversation  | Set an explicit provider matching the source native session, or perform the existing reviewed translation before changing it. Preserve the source owner; never interpret its ID under the current agent default.                                                                     |

No destructive migration is required for old data: absent fields preserve current behavior. Update serializers, equality keys, projections and shallow-copy allowlists so a new field is not silently dropped. Do not persist a launch-only projected agent back into the session store.

## Provider settings, Models, Auto and Run on

Use `providerOverridesFor(agent, provider)` for the selected provider's binary path, arguments, custom environment, custom provider path, model/effort defaults, context window/provenance and Claude token-source fields. It already reads live overrides for the default provider and parked overrides for other providers. Missing destination overrides fall back to that provider's global configuration and normal detection. Never copy the default harness's path, arguments, environment or context window onto another harness. Global environment and host/directory grants retain their current precedence; disabled environment values remain disabled.

Create one shared, pure launch projection in `providerSwap.ts`, built from `providerOverridesFor()` and the existing parking primitive. It returns the chosen provider's agent settings and native tab slot without changing the saved agent or other tabs. Every desktop/runtime send consumes that projection. It must explicitly clear outgoing provider-only keys before applying destination values; `{ ...session, toolType: destination }` is insufficient. Replace existing uses of `switchAgentProvider()` as a launch projection, which assume all tabs belong to the agent default.

| Code | Setting                | Resolution                                                                                                                                                                                                                                                                                          |
| ---- | ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| M1   | Named model and effort | Tab's selected provider slot, then `providerOverridesFor(agent, provider)`, then that provider's configured defaults. Validate effort against the selected provider; OpenCode has no effort control.                                                                                                |
| M2   | Tier targets           | When effective provider equals `agent.toolType`, keep `Session.tierTargets`. Otherwise omit agent tier targets and use `harnessTierDefaults[effectiveProvider]`, then existing built-in tiers. The choice is based on provider equality, not whether the tab is explicitly pinned.                  |
| M3   | Auto                   | Preserve `AUTO_MODEL` per provider. Call existing `resolveAutoTurn()` with the captured harness and that harness's routing inputs. System One chooses model tier/effort inside that harness. Preserve no-decision fallback and marker precedence; never send the literal `auto` to a provider.      |
| M4   | Run on selection       | Park tab `runOn` with model/effort. A missing tab value inherits `Session.runOn` only for the agent's default harness; another harness starts at `{ type: 'provider' }`. Explicit local-source choices must pass `parseRunOnEdit()` / `agentRunOnSupport()` for that harness and host.              |
| M5   | Run on launch          | Freeze the effective target, including explicit provider mode, in the send/queue snapshot. A resolved Auto tier can override that target using existing `turnRunOnTarget()` semantics. Both `turnRunOn` and `turnRunOnSource` come from the same resolved target.                                   |
| M6   | Gateway/proxy          | Preserve existing destination support checks. Do not inherit default-provider `gatewayUrl`, token-proxy or background-routing settings into a non-default harness. Inspect main-process persisted-record reads as well as renderer arguments; a correct UI projection alone cannot prevent leakage. |

Reusing a parked model or local source does not certify it is still available. Keep the selection, explain a missing endpoint or unsupported target, and refuse an invalid launch rather than silently using a cloud provider. Model and effort discovery, Auto support and Run on choices all use the same projected provider configuration.

### Queue and asynchronous routing contract

At enqueue, capture effective provider, selected model (including Auto), effort and effective Run on. Freeze the routing inputs relevant to Auto (the selected harness's tier overrides/defaults) with the item, and attach the router answer once it arrives. Later pill or settings changes cannot retarget that queued message. Resume/cache eligibility is checked at dispatch against the native slot actually being resumed; the router's answer is not requested a second time. A legacy snapshot without the new fields follows the current documented fallback, never guesses a provider from a model string.

Queue execution can use provider A while the visible tab selects B. Read A's native slot, attribute all events to A, and leave the visible selection at B. Successful A turns mark A as the latest source for a subsequent B send. A pending Auto answer must match the captured turn/queue item identity and provider before it settles; a late answer for a previous send cannot settle a newer pending turn. `settleAutoTurnOnTab()` currently only checks pending status, so this identity check is part of the migration.

Main-process spawn validation resolves the stored tab/provider and destination override set using the process's agent/tab identity. It validates captured Run on against existing endpoint and host rules. It must not reload the live agent's different Run on or Claude token mode over the snapshot. Headless APIs that have no tab remain agent-scoped; they do not borrow the desktop's active tab.

## Provider menu and safety explanations

Build rows from `PICKABLE_AGENT_IDS` / `AGENT_PICKER_META` and `getAgentDisplayName()`, using existing provider availability filtering/detection for the selected host. Never create a second hardcoded provider registry. Retain the current provider in the readout even if detection now fails. Under an installed-only filter, keep installed providers with unsupported directions visible and disabled. If unavailable rows are shown, disable them with the detection reason.

The current registry contains Antigravity, Claude Code, Codex, Copilot CLI, Factory Droid, Grok, Hermes, OMP, OpenCode, Pi and Qwen3 Coder. Terminal and Gemini CLI have no picker metadata. Only Claude Code -> Codex and Codex -> Claude Code have declared translation directions in `translation/support.ts`; both are `unverified`. This is a source snapshot, not an installed-provider claim.

| Code | Condition                                       | Row/message behavior                                                                                                                                                                                            |
| ---- | ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P1   | Current provider                                | Selected; no translation. Choosing "Use agent default" is offered separately and obeys the same destination checks if it changes provider.                                                                      |
| P2   | Declared local direction and provider available | Selectable; secondary text "Context translation is unverified; review required before sending." Existing plan warnings must still be accepted through the translation review flow. Selection is not acceptance. |
| P3   | No declared direction                           | Disabled: "Context translation from Claude Code to OpenCode is not available." Apply this rule even to an empty tab for this release, rather than exposing a second switching policy.                           |
| P4   | Provider missing or unable to run a chat turn   | Disabled with host-specific detection/capability reason, such as "Codex is not installed on this host."                                                                                                         |
| P5   | SSH agent                                       | Entire switch control disabled: "Provider switching over SSH is unverified; live SSH acceptance was skipped." No fallback to a local provider or another machine.                                               |
| P6   | Translation pending/recovery lock               | Show its existing progress or recovery reason. Do not accept a new conflicting switch while native apply/rollback owns the tab. A running ordinary turn alone is not this lock.                                 |

The menu's direction source is the latest native context owner when a translation is pending, not merely the highlighted destination. Returning to that owner cancels the pending hop. A future direction can be enabled over SSH only with recorded live evidence for that direction/version/host contract. The explicit skip records in [[provider-translation-layer]] are not such evidence.

## CLI contract

Proposed surface, implemented in the later UI/CLI phase:

```text
maestro-cli tab provider <tab-id> [<provider>] [--model <m>] [--effort <e>] [--json]
maestro-cli tab provider <tab-id> --inherit [--json]
maestro-cli session show <tab-id> --json
```

`tab provider <id>` reads effective provider, agent default, optional explicit pin, model, effort, Auto selection, Run on and pending translation state. With a provider it applies one atomic provider/model/effort change; reject invalid options before parking any state. `--inherit` is mutually exclusive with a named provider. `--model`/`--effort` without a provider modify the current effective slot. Existing `tab model` and `tab effort` must validate against that slot too. A tab-scoped Run on read/write must accompany the model menu's Run on action, reusing the existing Run on parser and provider/source syntax rather than changing the agent-wide target.

The new verb refuses both reads and writes with a clear `Ensemble is disabled` error when the flag is off, as ENSEMBLE-09 specifies. Generic `session show` remains usable and reports truthful persisted state regardless of the flag. Add `provider` (effective), `tabProvider` (explicit or null), `agentProvider` and `turnProvider` (captured or null), with model/effort/Run on and pending source metadata; never include environment secrets or arbitrary parked native data. Preserve existing JSON fields and their meanings. `session list` / `tab show` should expose equivalent provider metadata without reinterpreting a legacy `toolType` field silently.

The UI and WebSocket bridge call the same validated main-process service, which invokes the shared pure switch and the existing authoritative tab-store mutation callback. Add the preload/IPC and CLI types, request handler, validation, response mapping and older-host rejection together. Do not expose raw `tabProvider` through an unrestricted tab patch that bypasses availability or parking. No focus change, toast or foreground navigation is needed. A successful write returns the resulting tab state, so callers can verify it. Native warning acceptance remains in the existing plan/review flow; do not add an automatic acceptance flag to ordinary provider selection. Record the completed parity row in [[CLI-UI-PARITY]] when the action ships.

Core migration notes (2026-10-17): I01-I23 now share a one-tab launch projection across desktop, queue, remote and runtime sends. Native translation plans and commits use effective slot ownership; agent-wide operations skip pins. Queue captures freeze Run on and routing, and Auto answers are guarded by pending turn identity and provider. `turnSessionId` records the captured native identity and invalidates cache holds after an import replaces it. IDs, buffered usage, assistant transcript entries, History, synopsis and stats retain captured ownership. Queue producers in I13 already call the revised capture helper; retry refresh now stays inside its captured provider slot. I18's Auto Run execution has no tab and retains its captured agent default; its background synopsis receives the explicit completed provider and captured Run on from the exit path. I15's generic context loader, assembly, parser and launch layers remain provider-parameterized; callers project before invoking them. I23's Edit Agent path already requires native translation review, and runtime agent parking preserves explicit pins and captured queue items.
